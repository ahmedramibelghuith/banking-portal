# Banking Portal enhancement roadmap

The combined version provides customer sessions, account management, a ledger, and administrator views. The next improvements should strengthen correctness and operability before expanding the feature set.

| Priority | Enhancement                                 | Why it matters                                                                                                                    | Acceptance criteria                                                                                                                                                                    | Effort       |
| -------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| 1        | Transaction idempotency keys                | A network timeout can leave a customer unsure whether an operation completed. Retrying should not duplicate it.                   | Persist a unique request key and response per customer; repeated keys return the original result; test concurrent duplicate submissions.                                               | Medium       |
| 1        | Flyway schema and data migrations           | Development currently uses Hibernate `ddl-auto=update`; the old Digital-Bank schema has different credentials and monetary types. | Version the new schema, validate it on startup, test upgrade/rollback procedures, and provide a separately reviewed legacy import with balance reconciliation.                         | Medium       |
| 1        | MySQL integration tests with Testcontainers | H2 tests do not prove identical locking and persistence behavior on MySQL.                                                        | Run ownership, exact-money, concurrent withdrawal, rollback, and account-closure tests against the production database engine.                                                         | Medium       |
| 1        | Login throttling and account recovery       | Password verification exists, but there are no rate limits, password-reset flow, or verified-email workflow.                      | Rate-limit login/registration, expire one-time recovery tokens, verify email changes, and test abuse/expiration paths.                                                                 | Medium–large |
| 2        | Deployment configuration and monitoring     | Local startup is covered; a public environment needs explicit infrastructure settings.                                            | Deploy behind HTTPS with `COOKIE_SECURE=true`, same-origin `/api` routing, database secrets, health checks, structured logs without credentials, metrics, and tested backups/restores. | Medium       |
| 2        | Pagination, filtering, and statement export | Account history and admin lists currently return all matching rows.                                                               | Server-side bounded pagination, date/type filters, indexed queries, accessible controls, and CSV/PDF exports tested with large data sets.                                              | Medium       |
| 2        | Session-expiry recovery in the UI           | The API rejects expired sessions; actions show an error and the customer may need to sign in again manually.                      | Centralize 401 handling, redirect to sign-in, preserve safe navigation intent, and avoid automatically retrying money requests.                                                        | Small        |
| 2        | Currency and ledger policy                  | The UI currently displays USD and the model is single-currency. Savings interest and overdraft policies are not executed.         | Store currency explicitly, validate matching transfer currencies, define rounding and overdraft rules, and implement scheduled interest with an auditable reference.                   | Large        |
| 3        | Accessibility and UI refinement             | Responsive forms and accessible dialogs are a starting point.                                                                     | Automated accessibility checks plus keyboard/screen-reader testing, per-field validation messages, locale-aware dates, mobile tables, and French/English translations.                 | Medium       |
| 3        | Separate cash-operation permissions         | Customer deposits currently simulate crediting the local ledger.                                                                  | Integrate a payment provider or restrict cash credits/debits to a teller role, with approval and reconciliation rules.                                                                 | Large        |

Keep Digital-Bank as the reference archive. Implement new changes in Banking Portal to avoid maintaining two diverging active applications. The existing database must be backed up and migrated explicitly if its records are needed; copying the source does not move the data.
